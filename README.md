# Date ERP / MfgSystem

## الحالة الحالية

هذا هو **المصدر الحالي الوحيد** لنظام إدارة وتصنيع التمور، الإصدار `1.50.74`.
اسم البرنامج التنفيذي هو `MfgSystem.exe`، والمشروع مبني بتقنية WPF على `.NET 8`.

تم دمج نظام إدارة الثيم المركزي في هذه النسخة، ويشمل الألوان والخطوط والحقول والأزرار والجداول والنوافذ وأوضاع Light/Dark/Auto، مع الحفظ داخل `SystemSettings` وحماية شاشة التخصيص بصلاحية `settings/Edit`.

> هذه شجرة المصدر الحالية وليست مستودعاً لأرشيفات التحديثات السابقة. تم الاحتفاظ بملف `UPDATE_1.50.73_FULL_SOURCE_BUILDABLE.zip` وحده كمرجع ثبات إلزامي، ولا يُستخدم للتشغيل أو التطوير.

## الحل الرسمي

يُستخدم ملف الحل الوحيد التالي:

```text
DateERP.sln
```

ويضم مشاريع المصدر والاختبارات وأدوات القبول والفحص اللازمة للمشروع الحالي.

## البناء والتشغيل

يتطلب البناء والتشغيل الفعلي Windows 10/11 مع .NET 8 SDK؛ كما يحتاج سكربت الحزمة Python 3 مع مشغّل `py` لفحوصات السياسات.

### البناء والاختبارات

```bat
dotnet restore DateERP.sln
dotnet build DateERP.sln -c Release
dotnet test tests\DatesErp.Tests\DatesErp.Tests.csproj -c Release
```

### تشغيل نسخة التطوير

```bat
dotnet run --project src\DatesErp.Desktop\DatesErp.Desktop.csproj
```

### تحديث مصدر العمل

`UpdateProject.vbs` أداة اختيارية لنسخ المصدر 1.50.74 فقط إلى شجرة مصدر منفصلة من الإصدار نفسه؛ ترفض Git working trees والإصدارات الأخرى مثل 1.50.73، ولا تنسخ الأرشيفات أو بيانات التشغيل ولا تحذف ملفات الوجهة. ليست مثبّتاً ولا تنتج ملفاً تنفيذياً.

### إنشاء حزمة Windows

من Windows فقط، وباستخدام .NET 8 SDK:

```bat
Installer\1-بناء_الحزمة.bat
```

ينفذ السكربت `dotnet restore` و`dotnet build DateERP.sln -c Release` واختبارات الحل ثم ينشر حزمة `win-x64` self-contained. المخرجات ذات إصدار ثابت:

```text
artifacts\MfgSystem_1.50.74_win-x64\
artifacts\MfgSystem_1.50.74_win-x64.zip
```

بعد اكتمال بناء واختبار Windows بنجاح، انقل المجلد/ZIP كاملاً إلى الجهاز الهدف وشغّل `2-تنصيب.bat` داخله. يتحقق المثبّت من الإصدار وSHA-256 ويُنشئ اختصاراً باسم `MfgSystem 1.50.74`.
البيانات والإعدادات المحلية محفوظة في `%LOCALAPPDATA%\MfgSystem\1.50.74`؛ لا يقرأ المثبّت أو التطبيق إعدادات إصدار أقدم ولا يعتمد على مجلد نشر قديم.

## قاعدة البيانات والاتصال

- قاعدة SQLite المحلية الجديدة: `%LOCALAPPDATA%\MfgSystem\1.50.74\mfgsystem_local.db`.
- إعدادات الاتصال والسجلات والمسودات محفوظة تحت `%LOCALAPPDATA%\MfgSystem\1.50.74`.
- أول تشغيل ينشئ إعداداً وقاعدة محلية جديدين؛ لا تُقرأ أو تُهاجر إعدادات أو قواعد إصدارات سابقة تلقائياً.
- يمكن لمسؤول النظام اختيار SQL Server من شاشة إعداد الاتصال؛ تبقى بيانات الإعداد الخاصة بالتطبيق معزولة في مجلد الإصدار.
