# دليل ترقية الإصلاحات — 8 سبتمبر 2026

هذه التغييرات مبنية على الفرع `arena/01a081d0-tasnee1212` عند commit `e17ed68`.
لم تُغيّر أعمدة قاعدة البيانات أو قواعد توازن المخزون أو مدد المعالجة.

## قبل تحديث جهاز الإنتاج

1. خذ نسخة احتياطية موثوقة بوسائل SQL Server المعتمدة واختبر استعادتها إلى قاعدة منفصلة.
2. ابنِ وانشر من المصدر الحالي؛ أرشيفات B109 والإصدارات الأقدم داخل المستودع لا تشمل هذه التعديلات.
3. جرّب الإصدار على جهاز Windows غير إنتاجي وقاعدة اختبار قبل التعميم.
4. لا تكفي إعادة تثبيت .NET لتحديث النسخ self-contained القديمة؛ أعد النشر من المشروع المعدّل.

## تغيير مهم في اتصال SQL

- استُبدل دمج النصوص بـ `SqlConnectionStringBuilder` مشترك بين التطبيق وفحص الاتصال. كلمات المرور المحتوية على `;` أو الاقتباسات تُعامل كقيم كاملة، لا كخيارات اتصال إضافية.
- أصبح `Encrypt=Mandatory` و`TrustServerCertificate=False` افتراضيين.
- يشمل الافتراضي الآمن ملفات `config.json` القديمة التي لا تحتوي الخاصية الجديدة.
- يعني ذلك أن خادماً بشهادة ذاتية أو غير موثوقة قد لا يقبل اتصال النسخة الجديدة حتى تُضبط الثقة. هذا تغيير مقصود، وليس عودة لعطل كلمة المرور.

### الإنتاج

ثبّت شهادة خادم موثوقة وسلسلة شهادات صحيحة، واستخدم اسماً في الاتصال يطابق اسم الشهادة. أبقِ خيار «السماح بشهادة تطوير غير موثوقة» غير محدد. لا تستخدم هذا الخيار كحل دائم لمشكلة شهادة إنتاج.

### بيئة تطوير مع شهادة ذاتية فقط

يمكن تحديد الخيار الصريح في شاشة إعداد الاتصال، ثم إعادة اختبار الاتصال وحفظ الإعداد. التشفير يبقى إلزامياً، لكن التحقق من هوية الخادم يُتجاوز؛ لذلك الخيار غير مناسب للإنتاج.

في MRMRTT 1.50.74، إعداد الاتصال الخاص بهذا الإصدار في `%LocalAppData%\MfgSystem\1.50.74\config.json`. إذا تعذر الوصول إلى شاشة الإعداد، أغلق التطبيق وخذ نسخة آمنة من هذا الملف قبل أي تعديل إداري. لا يقرأ هذا الإصدار ملف إعداد الإصدارات السابقة ولا يهاجره تلقائياً. الخاصية هي `TrustServerCertificate` وقيمتها الآمنة `false`. لا تنشر أو تشارك ملف الإعداد أو أسرار SQL.

كل تغيير في الخادم أو القاعدة أو المصادقة أو كلمة المرور أو خيار الشهادة يعطّل الحفظ حتى نجاح فحص جديد.

## CI والاختبارات

التعريف الوحيد في `.github/workflows/ci.yml`، ويعمل بعد رفعه إلى GitHub. يشمل Windows وLinux، وبناء Release نظيفاً مع `-warnaserror`، ثم الاختبارات وأداتي القبول والتدقيق.

أُصلح اختبار المعالجة بإعادة جلب كيان EF بعد التراجع؛ لم يُعطّل شرط مدة المعالجة. وأُحدّث اختبار بنية التخطيط إلى عناصر الملخص الحالية، مع استمرار اختبارات حساب الطاقة القائمة.

حارس `double` صار قائمة بأسماء الأعضاء القديمة بدلاً من سقف عددي غير دقيق. هذه قائمة توافق موثّقة، **لا إصلاح لنوع الأعمدة ولا ادعاء بإزالة الدين التقني**. التحويل إلى decimal يتطلب مشروع ترحيل مستقل واختبارات مالية ومخزنية.

## ما لم تثبته اختبارات هذه البيئة

الفحص المحلي تم على Linux. لم تُجر تجربة تفاعلية لواجهة WPF أو المثبّت أو الطباعة أو الاسترجاع أو التزامن على خادم SQL فعلي. يجب إجراء هذه الخطوات قبل اعتماد النسخة للإنتاج.

لم تُعدَّل خدمة النسخ الاحتياطي في هذه الحزمة: سلوكها الحالي خاص بـSQL Server، وإنشاء المجلد وسرد النسخ محليان على جهاز العميل. عند العمل بخادم بعيد لا تفترض أن `C:\...` على جهاز العميل هو نفسه على الخادم. استخدم أدوات SQL Server الإدارية للنسخ والاسترجاع إلى أن يُختبر ويُعاد تصميم هذا الجزء على بيئة خادم فعلية. لا تستخدم شاشة النسخ الحالية لنسخ SQLite.

لم تتغير سياسة الحسابات المبذورة: غيّر كلمات التهيئة فوراً وعطّل الحسابات غير المستخدمة. كذلك ما زال مسار حماية إعدادات SQL خارج Windows يستعمل Base64 للاختبارات فقط؛ لا تنشره كآلية تشفير في نظام إنتاج غير Windows.
